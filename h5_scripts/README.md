# h5_scripts — вырезка Душанбе из NISAR L2 (GCOV / GUNW)

`crop_dushanbe.py` вырезает из HDF5-файлов NISAR квадрат Душанбе
(bbox `68.68, 38.48, 68.88, 38.62`, проекция UTM 42N / EPSG:32642)
и сохраняет его в лёгкие GeoTIFF (~3.5 МБ вместо ~2 ГБ). С диска читается только нужное окно.

Результаты пишутся **вне репозитория** — в `../data/raw_nisar/` рядом с папкой проекта
(например `~/github/data/raw_nisar/` для `~/github/honainav`). Папку можно сменить флагом `-o`
или переменной окружения `HONAINAV_DATA` (тогда результат будет в `$HONAINAV_DATA/raw_nisar`).

## Установка
```bash
pip install -r h5_scripts/requirements.txt
```

## Запуск
Входная папка по умолчанию — `../data/raw` (туда качает `getdata_scripts/download_nisar.py`);
другие папки/файлы можно перечислить аргументами.
```bash
# 1. Посмотреть структуру файлов, найденные сетки и окно Душанбе (ничего не пишет)
python3 h5_scripts/crop_dushanbe.py /path/to/nisar --info

# 2. Основной ряд: трек 012, восходящая орбита, кадр 021
python3 h5_scripts/crop_dushanbe.py /path/to/nisar --track 12 --direction A --frame 21
```

## Результат (`../data/raw_nisar/`)
| Файл | Каналы |
|---|---|
| `dushanbe_gcov_YYYYMMDD.tif` | `HHHH`, `HVHV` — gamma0, линейные единицы (в дБ переводит аналитика) |
| `dushanbe_gunw_REF_SEC.tif` | `unwrappedPhase` (рад), `coherenceMagnitude` (0..1) |
| `manifest.csv` | список всех tif (имя файла относительно этой папки): дата, цикл, трек, орбита, кадр, слои, размер |

Снимки с нисходящей орбиты получают суффикс `_D<track>`, чтобы не смешиваться с основным рядом.

## Полезные флаги
- `--product GCOV` — только GCOV (по умолчанию GCOV и GUNW)
- `--layers HHHH HVHV numberOfLooks` / `--layers all` — какие слои брать
- `--bbox LON_MIN LAT_MIN LON_MAX LAT_MAX` — другая область
- `--cog` — Cloud-Optimized GeoTIFF
- `-j 4` — параллельная обработка; `--overwrite` — пересчитать готовые

# analyze_complexes.py — стройактивность по полигонам ЖК

Берёт вырезки из `../data/raw_nisar/` и GeoJSON с полигонами ЖК, считает по каждому ЖК
сигнал с вычетом фона, индексы SCI/AVI, когерентность и смещение грунта, ставит вердикт
и рисует PNG для фронта.

```bash
python3 h5_scripts/analyze_complexes.py geojson/complexes_dushanbe.geojson
```

## Как считается
| Шаг | Что делает |
|---|---|
| site | полигон ЖК, расширенный на 1 пиксель (`--layover-m`) в сторону спутника — компенсация layover (восходящая орбита → на запад) |
| ring | кольцо 100–400 м вокруг ЖК (`--ring-inner/--ring-outer`) без других стройплощадок — «спокойный фон» |
| norm_hh_db | `10·log10(mean site) − 10·log10(median ring)` — убирает дождь, влажность, калибровку |
| SCI | среднее последних 2 дат − среднее первых 2 дат (norm HH), дБ |
| AVI | среднее \|norm(t+1) − norm(t)\|, дБ |
| coh_drop | когерентность ring − site (GUNW); земляные работы разрушают когерентность |
| ground_shift_mm | смещение по лучу зрения (LOS) в кольце **относительно города**, сумма по цепочке пар GUNW. Фаза: −ионосфера, −медиана своей связной области, −плоскость по городу (плавные градиенты атмосферы; `--no-detrend` отключает), × −λ/4π |
| ground_shift_sigma_mm, z | погрешность: робастный разброс (1.4826·MAD) того же смещения в кольцах вокруг 400 случайных точек города; z = смещение / σ |
| ground_risk_level | < 5 мм или < 2σ → `stable`; < 15 мм → `moderate_shift`; иначе `high_risk` |
| site: навал | полигон расширяется к спутнику на 1 пиксель (`--layover-m`). `--layover-by-floors` — расширение на H / tan(угла падения) по этажности (`max_floors`); на реальных данных Душанбе широкая маска размывала сигнал строек, поэтому по умолчанию выключено |
| вердикт | `nisar_pixels < 4` → `insufficient_resolution`. Иначе ЖК сравнивается с 200 случайными участками города **того же размера и маски** (`--calib-n`): признаки объединяются методом Фишера по эмпирическим рангам. Сильнее 95% участков → `activity_detected`, сильнее 90% → `possible_activity`, иначе `no_changes`. Ложные срабатывания ≈ 100 − перцентиль для любого размера ЖК. `--threshold-rule` — старое правило «любой признак > p95» (на маленьких участках даёт много ложных срабатываний — см. лог калибровки) |
| confidence | пиксели × доля дат × удалённость от порога, 0..100 |

Размер пикселя берётся из tif — при переходе на данные лучшего разрешения ничего менять не нужно.

**Пороги** по умолчанию — 95-й перцентиль тех же величин (|SCI|, AVI, падение когерентности)
на 400 случайных площадках города размером с типичный ЖК («сильнее, чем у 95% обычных кварталов»).
Значения пишутся в лог и `city_stats.json`. `--plan-thresholds` — фиксированные пороги из плана
(1.8 / 1.2 / 0.25), `--t-sci/--t-avi/--t-coh` — задать вручную.

## GSLC — детальный слой (10×5 м)
Если в `raw_nisar/` есть хотя бы два `dushanbe_gslc_*.tif` (их делает `crop_dushanbe.py` из
файлов `getdata_scripts/download_nisar.py`), по паре первая/последняя дата считаются:
- **когерентность** в окне `--gslc-window-m` (40 м ≈ 4×8 px) — карта и среднее в site/ring;
  падение когерентности внутри ЖК = поверхность менялась между датами;
- **ΔдБ** — изменение яркости HH (site минус фон кольца) между датами.

Пороги — p95 шума случайных площадок города (`--t-gslc-coh`, `--t-gslc-sci` — вручную).
Флаг `topographicFlatteningApplied` из исходного файла пишется в tif; если он `False`,
скрипт предупредит, что когерентность занижена полосами рельефа.
Поле `triggers` в результате перечисляет, какие признаки превысили порог
(`gcov_sci`, `gcov_avi`, `gunw_coherence`, `gslc_coherence`, `gslc_sci`).
